# Research Grant Management System (RGMS) — MVP Phase 1

ระบบสารสนเทศเพื่อบริหารจัดการทุนวิจัยงบประมาณเงินรายได้ มหาวิทยาลัยแม่ฟ้าหลวง (มฟล.) ครอบคลุมกระบวนการดำเนินงานช่วง Pre-Award ตั้งแต่การประกาศเปิดรับทุน การยื่นข้อเสนอโครงการ การตรวจสอบระดับสำนักวิชา การพิจารณาแบบ 2 แทร็กคู่ขนาน จนถึงการอนุมัติมติและออกประกาศผลจัดสรรทุน

---

## 1. ภาพรวมโครงการ (Project Overview)

โครงการ RGMS MVP Phase 1 พัฒนาขึ้นเพื่อแก้ปัญหาความล่าช้า ความซ้ำซ้อน และความผิดพลาดในการจัดการเอกสารและงบประมาณ โดยยกระดับจากระบบเอกสารเดิมเข้าสู่ระบบดิจิทัลแบบ centralized platform เน้นการตรวจสอบกฎระเบียบอัตโนมัติ (Automated Rule Engine) และการเร่งรัดกระบวนการประเมินด้วยสถาปัตยกรรม 2 แทร็กคู่ขนาน

* **ขอบเขตการทำงาน (In Scope):** ครอบคลุมเฉพาะกระบวนการ Pre-Award (ยื่นข้อเสนอ $\rightarrow$ ตรวจสอบ $\rightarrow$ พิจารณา $\rightarrow$ ประกาศผลทุน)


* **นอกขอบเขต (Out of Scope):** การทำสัญญา, การเปิดบัญชี, การเบิกจ่ายงวดเงิน (50/40/10), การส่งรายงานความก้าวหน้า และการปิดโครงการ (ยกยอดไปพัฒนาใน Phase 2)

## 3. สถาปัตยกรรมกระบวนการพิจารณา 2 แทร็กคู่ขนาน (Parallel Dual-Track Architecture)

```
                       [นักวิจัย ยื่นข้อเสนอโครงการ]
                                     │
                                     ▼
                    [ประธานวิจัย/คณบดี Endorse (FR-74)]
                                     │ (ผ่าน)
                                     ▼
                    [เจ้าหน้าที่วิจัย ตรวจ Screening (FR-15)]
                                     │
         ┌───────────────────────────┴───────────────────────────┐
         ▼ แทร็กเนื้อหา (FR-77)                                 ▼ แทร็กการเงิน (FR-83)
  คณะอนุกรรมการประเมินวิชาการ                            จนท.การเงิน Claim ตรวจตาราง 17.2
  (Comment-based / ไม่ใช้ Rubric)                       (ตรวจเพดานงบ & กฎ 25% Sub-cap)
         │                                                       │
         └───────────────────────────┬───────────────────────────┘
                                     ▼
                    [Revise Loop & Field Locking (FR-84)]
                    - แทร็กที่ "รับรองแล้ว" -> ล็อก UI เป็น Read-Only
                    - แทร็กที่ "ติด Comment" -> ส่งกลับตรวจซ้ำเฉพาะแทร็กเดิม
                                     │
                                     ▼ (เมื่อรับรองผ่านทั้ง 2 แทร็ก)
                    [คกก.ส่งเสริม พิจารณาลงมติ (FR-85)]
                                     │
                                     ▼
                    [ออกประกาศผลทุน & แจ้งเตือน (FR-59)]

```

## 4. สรุปการแก้ไขช่องโหว่และจุดปรับปรุงสำคัญ (V1 vs V2 Comparison)

1. **ป้องกันการแอบแก้ไขข้อมูล (Data Integrity):**
* *ปัญหาเดิม (V1):* เมื่อส่งกลับไปแก้ไข นักวิจัยสามารถเปิดแก้ฟิลด์ข้อมูลได้ทุกส่วน


* *การแก้ไข (V2):* ทำระบบ **Field-Level UI Locking** ล็อกฟิลด์ที่ผ่านการรับรองแล้วเป็น Read-Only ถาวร และใช้ตรรกะ **Auto-Route Revise Loop** ส่งเฉพาะแทร็กที่ไม่ผ่านกลับไปให้ผู้ตรวจเดิมโดยอัตโนมัติ




2. **ขจัดคอขวดกระบวนการ (Workflow Bottlenecks):**
* *ปัญหาเดิม (V1):* การตรวจเป็นแบบอนุกรม ข้ามการคัดกรองระดับสำนักวิชา และไม่ระบุผู้รับผิดชอบขั้นตอนปัจจุบัน


* *การแก้ไข (V2):* แยกตรวจ 2 แทร็กคู่ขนาน เพิ่มด่านคัดกรอง **School Endorse Gate** และแสดง **Pending Responsibility Bar** ระบุตัวผู้รับผิดชอบปัจจุบันบนหน้าจอชัดเจน




3. **ควบคุมความถูกต้องของงบประมาณ (Financial Compliance):**
* *ปัญหาเดิม (V1):* ตรวจสอบงบด้วยมือ ปล่อยให้ยื่นงบเกินเพดานประเภททุนหรือเกินเพดานย่อย 25%


* *การแก้ไข (V2):* เพิ่ม **Automated Rule Engine** คำนวณเพดานงบ Per-Tier อัตโนมัติ บล็อกทันทีหากค่าเดินทางหรือครุภัณฑ์ >25% และอ่านไฟล์ Excel 17.2 สดผ่าน SheetJS




4. **จัดการสิทธิ์และติดตามการทำงาน (Access Control & Audit Trail):**
* *ปัญหาเดิม (V1):* สิทธิ์ค้างใน `localStorage` และไม่มีระบบผูกตัวผู้ตรวจการเงิน


* *การแก้ไข (V2):* เพิ่ม **Role Auto-Sync Engine** ปรับสิทธิ์ตาม URL อัตโนมัติ และผูกเจ้าหน้าที่การเงินผู้กด Claim เป็นผู้รับผิดชอบถาวรพร้อมบันทึกประวัติหากมีการ Reassign




5. **ควบคุมเวลาและลดงานซ้ำซ้อน (Operations):**
* *ปัญหาเดิม (V1):* ยื่นข้อเสนอนอกเวลาเปิดรับทุนได้ และนักวิจัยต้องพิมพ์ข้อมูลใหม่ทุกครั้ง


* *การแก้ไข (V2):* บล็อกปุ่มยื่นทันทีเมื่อปิดรอบทุน และเพิ่มระบบดึงข้อมูลจากโปรไฟล์ พร้อมสกัดข้อความจากไฟล์ Word RS-01 (.docx) ลงฟอร์มอัตโนมัติ

## 6. แนวทางการติดตั้งและใช้งาน (Getting Started)

### ความต้องการของระบบ (Prerequisites)

* Web Browser เวอร์ชันล่าสุด (Google Chrome, Microsoft Edge, Mozilla Firefox หรือ Safari)
* ไม่ต้องติดตั้ง Web Server หรือ Node.js เนื่องจากระบบถูกออกแบบโครงสร้างเป็น Client-side Prototype (Static HTML/CSS/JavaScript)

### ขั้นตอนการเปิดใช้งาน

1. ดาวน์โหลดหรือ Clone คลังเก็บโค้ดลงเครื่องคอมพิวเตอร์
2. เปิดไฟล์ `index_2.html` ผ่าน Web Browser


3. เลือกรอบการทำงานหรือบทบาททดสอบ (เช่น นักวิจัย, ประธานวิจัย, เจ้าหน้าที่วิจัย, เจ้าหน้าที่การเงิน, คณะอนุกรรมการ)


4. ทดสอบฟังก์ชัน Command Palette โดยการกดปุ่ม `Cmd + K` (macOS) หรือ `Ctrl + K` (Windows) เพื่อสลับหน้าการทำงานอย่างรวดเร็ว
